# 飞飞历险记 · 联网优化方案 V2
> 身份体系 · 防刷防耗 · 排行榜规则 · 2026-08-14

## 一、问题现状（V1 联网的局限）

| # | 问题 | 现状 | 风险 |
|---|---|---|---|
| 1 | 身份 | 纯昵称（localStorage 记忆），无设备绑定 | 换设备手动输昵称；任何人可冒用他人昵称 |
| 2 | 同名 | 不区分：云存档互相覆盖、榜单合并 | 数据错乱、榜单失真 |
| 3 | 盗用 | HMAC 密钥前端可见、按昵称限频可绕过 | 伪造高分刷榜、KV 写入额度被耗尽（1000/天） |
| 4 | 日榜 1200 | 关卡长度 1200 = 满分 | 通关后无区分度（同分并列多） |

## 二、优化方案

### P3-1 匿名设备 ID + 昵称分离（解决 1/2）

```
身份 = deviceId（匿名 UUID，localStorage 生成）+ nickname（展示名）
```

- **deviceId**：首次打开生成 `crypto.randomUUID()` 存 localStorage —— 同一设备天然是"同一个人"
- **nickname**：纯展示（排行榜显示用），不再作为身份键
- **云存档 key**：`save:<deviceId>`（不再是 `save:<昵称>`）→ 同设备自动同步，**同名不会互相覆盖**
- **换设备**：手机/PAD 首次打开生成新 deviceId → 云存档不会自动跟过来 → 提供**迁移码**机制（见下）

**换设备迁移（轻量绑定）**：
1. 旧设备"设置"里生成**6 位迁移码**（服务端绑定 deviceId）
2. 新设备输入迁移码 → 服务端把存档从旧 deviceId 复制到新 deviceId（一次性）

> 比账号密码轻量得多；比纯昵称可靠得多。未来要强登录再接 Cloudflare Access / 微信 OAuth。

### P3-2 防刷防耗（解决 3）

**A. 服务端限流（按 IP + deviceId 双重）**：
- Worker 取 `CF-Connecting-IP`（Cloudflare 自带真实 IP 头）
- 限频：`同一 IP 每 60 秒最多 3 次提交` + `同一 deviceId 每 60 秒 1 次`
- KV key：`rl:ip:<ip>` / `rl:dev:<deviceId>`（TTL 60s）

**B. KV 写入熔断（防额度耗尽）**：
- 每日写入计数 `daily:writes:<date>` 递增，**达到 800 次（额度 1000 的 80%）拒绝写入并返回 503**
- 保护正常玩家配额，攻击者无法挤掉真实成绩

**C. 分数校验强化**：
- 提交附带**轨迹摘要**：`{ hits, energyUsed, maxCombo, playSeconds }`（游戏内统计）
- 服务端校验：分数与轨迹的**合理性比例**（如 1200 里程至少对应一定命中次数），明显不匹配拒绝
- 同 deviceId **分数单调性**：新提交必须 ≥ 历史提交的 90%（防反复刷低分干扰，高分刷不了）

**D. HMAC 强化（尽力而为）**：
- 密钥定期轮换（服务端按日期派生 `SECRET + date`）
- 前端代码混淆（作用有限，**不做** —— 诚实标注：前端防作弊天花板低，重防依赖服务端权威计分 P4）

### P3-3 日榜同分规则（解决 4）

每日挑战**通关后继续计时**：
- 成绩 = `{ 里程, 用时 }`
- 排序：里程降序 → 里程相同**用时升序**（更快者胜）
- 通关 1200 的玩家按用时排名，不再千人并列

### P3-4 存档大小与数据卫生

- 存档 PUT 校验 body ≤ 20KB（防大 payload 撑爆 KV）
- 榜单条目 ≤ 200 条；旧日榜（>7 天）自动清理（KV TTL：日榜 key 设 expirationTtl 7 天）
- 昵称/deviceId 长度校验（≤ 20 / ≤ 64）

## 三、API 变更

| 端点 | 变更 |
|---|---|
| `/api/rank/submit` | body 加 `deviceId` + `trail`（轨迹摘要）；服务端按 IP+deviceId 限流 |
| `/api/save/put·get` | key 从昵称 → deviceId；迁移码专用端点 |
| `/api/migrate/create` | POST {deviceId} → 返回 6 位码（TTL 24h） |
| `/api/migrate/apply` | POST {code, newDeviceId} → 复制存档 |
| `/api/rank/top` | 返回条目带 deviceId 指纹（前 8 位）区分同名 |

## 四、前端改动

1. `network/api.ts`：deviceId 管理（生成/读取/随请求发送）
2. 设置面板（排行榜弹窗内）：显示 deviceId 指纹 + 生成/输入迁移码
3. 游戏内统计轨迹（hits/energyUsed/maxCombo/playSeconds）收集
4. 排行榜同名显示：`昵称#指纹前4位`（如 `jack#a3f2`）

## 五、分阶段

| 阶段 | 内容 | 工作量 |
|---|---|---|
| P3-1 | deviceId 身份 + 存档改键 + 迁移码 | ~1 天 |
| P3-2 | IP/设备双限流 + 写入熔断 + 轨迹校验 | ~1 天 |
| P3-3 | 日榜用时规则 + 数据卫生 | ~半天 |

## 六、诚实声明

- 前端 HMAC 的密钥**永远可以被提取** —— 防小白，不防高手
- 真正的强防作弊需要**服务端权威计分**（P4：服务端跑同一份关卡模拟验证分数，成本高，适合每日挑战这种短关卡）—— 若日活破千再考虑
- 匿名 deviceId 满足 99% 个人小游戏场景；要做正式账号体系再接 OAuth
