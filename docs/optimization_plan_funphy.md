## 0. 现状诊断（代码审计结论）

### 0.1 架构现状

| 模块 | 现状 | 问题 |
|------|------|------|
| 渲染 | `SceneRenderer`：整关世界缩放铺满 Canvas，`setWorldSize()` 计算统一 scale | **世界 = 屏幕**，无摄像机概念，关卡只能是一屏大小 |
| 物理 | `PhysicsEngine`：帧驱动，`engine.update(rt, 1)` **dt 硬编码为 1** | 物理速度随帧率变化（120Hz 屏会快一倍）；`timeAccumulator`/`lastTime` 声明了但从未使用 |
| 碰撞 | 圆-矩形碰撞 + 反弹解析（含防抖 hack） | 高速时可能穿透（无子步进）；无单向平台、无传送、无弹力垫等高级碰撞类型 |
| 触发器 | 引擎只实现 `boost` / `slow` / `wind` | **`gravity_well` 在数据中用了 11 次但引擎未实现**（第五章引力星关卡实际失效） |
| 关卡 | 30 关全部实现（6章×4普通+Boss），JSON 配置化 | 机制同质化：绝大多数是"障碍物+收集品+终点"三件套，关间差异主要靠物理参数数值 |
| 目标类型 | 只有"到达终点"（`goal.maxSpeed` 支持限速着陆） | 无收集赛/生存/竞速等多样目标 |
| 输入 | 4 方向键 + 摇杆（`thrustDir` 归一化向量） | 只有推力方向，无冲刺/蓄力等节奏操作，操控深度不足 |
| 失败模式 | 仅 `timeLimit` 超时失败 | 无掉落出界、碰撞上限等失败机制，压力感弱 |
| 进度 | `localStorage` + `SCHEMA_VERSION` 版本控制 | ✅ 结构良好，可平滑迁移 |

### 0.2 核心结论

游戏骨架完整、代码整洁，但**可玩性天花板被三个结构性限制卡住**：
1. **单屏世界**：关卡无法做大，缺乏探索感和纵深
2. **帧率相关物理**：手感在不同设备不一致，后续手感调优无从谈起
3. **机制单一**：物理实体类型少（只有障碍物/收集品/触发器三件套），关卡设计巧思施展不开

## 1. 对标分析（成熟游戏参考）

### 1.1 参考游戏与借鉴点

| 游戏 | 借鉴点 | 对应优化项 |
|------|--------|-----------|

| **Jetpack Joyride / Asteroids** | 推力型操控的经典手感：软限速（推力效率随速度下降）、惯性滑行 | §2.4 手感 |
| **Alto's Adventure / Sky** | 跟随相机 + 运动方向前瞻 + 视差多层背景 | §3 摄像机 |
| **Super Mario Galaxy / Osmos** | 星球引力场（局部引力源）、轨道运动 | §2.3 力系统（gravity_well） |

| **Angry Birds / Rayman** | 每关三星目标、收集品布局引导路线 | §4 关卡数据 |
| **Limbo / Inside** | 镜头缓慢推拉、氛围背景层 | §3.3 视差 |

### 1.2 提炼出的设计原则

1. **手感优先**：物理引擎的终极目标是"可控的惯性"——既要有惯性（教学点），又不能失控（挫败感）
2. **相机即叙事**：镜头引导视线，先看到目标再规划路线
3. **一关一机制**：每关只教一个核心概念，机制间不混战（呼应"先玩后悟"理念）
4. **失败要快**：快速重试降低挫败感，鼓励尝试（SM 肉男孩原则）

## 2. 物理世界引擎优化

### 2.1 帧率无关的固定时间步长（P0）✅ 已实施

**目标**：物理在任何帧率下表现一致（60/90/120Hz、低端机 30fps）。

**实施方式**（`useGameLoop.ts` + `PhysicsEngine.update()`）：
```
// 物理保持 60Hz 固定节拍，渲染跟随 rAF（显示帧率无关）
realDt = (rAF时间差) / 16.667            // 归一化到 60fps 帧单位，上限 5 帧
accumulator += realDt
while (accumulator >= 1 && steps < 5) {  // 最多补 5 步，防死亡螺旋
  engine.update(rt, 1)                   // 固定 dt=1
  accumulator -= 1
}
// 引擎内部再子步进：update 把 dt=1 拆成 2×0.5，防高速穿透
```
- 保留了原有"每帧单位"参数体系（`thrust 0.07` 等），**30 关数据零迁移**，手感与调优成果不破坏
- `slow` 触发器按步长缩放（`1 - 0.05*dt`），子步进下总效果不变
- 与方案初稿（换算为每秒量 + 120Hz）的差异：**用"固定 60Hz + 子步进"达到同样的帧率无关目标，但免去全部参数换算**，回归风险更低

### 2.2 碰撞系统增强（P0）

1. **子步进防穿透**：高速移动时每帧物理步内再分 2-4 子步检测，杜绝高速穿墙（当前 `thrust` 上限低所以没暴露，冲刺加入后必须做）
2. **新增碰撞类型**（types.ts 扩展）：

| 类型 | 行为 | 用途 |
|------|------|------|
| `platform`（单向平台） | 仅从上方碰撞，从下方/侧面穿过 | 跳跃峡谷、过山车 |
| `spring`（弹力垫） | 接触即施加固定弹力（带方向） | 弹力星跳板 |
| `conveyor`（传送带） | 表面施加持续切向力 | 阻力星、能量星 |
| `hazard`（危险区） | 接触即失败/扣碰撞次数 | 陨石带、暴风雪 |
| `oneway-wall` | 仅单侧碰撞 | 迷宫关 |

3. **碰撞响应分级**：静态障碍（反弹）→ 平台（单向）→ 弹力垫（施力）→ 危险（失败），按类型分发处理函数，替换现有单一 `resolveObstacleCollision`

### 2.3 力系统完善（P0/P1）

1. **实现 `gravity_well`（引力井）** ✅ 已实施：修复现有失效关卡
   ```
   对每个引力井：以区域中心为圆心，半径 R = max(w,h)/2 的圆形力场
   方向：指向井心（force>0 拉扯）/ 远离井心（force<0 推离）
   大小：恒定 |force|（与现有 boost/wind 语义一致），核心 0.5 单位死区防抖动
   ```
   设计文档 §5 引力星的关卡（轨道、弹弓、三体）全部依赖此机制
2. **风区增强**：支持场内渐变力（按 x 位置线性插值力度），暴风雪 Boss 用
3. **软限速**：速度越接近 `maxSpeed`，推力效率越低（`thrust_eff = thrust * (1 - v/v_max)²`），自然形成终端速度——阻力星主题直接受益，且全游戏手感更稳

### 2.4 手感优化（Game Feel）（P1）

- **推力平滑**：`thrustDir` 变化时用指数插值平滑，避免摇杆跳变导致抖动机身
- **屏幕震动**：碰撞时相机/画布微震（幅度随碰撞速度），参考 Celeste
- **粒子效果**：尾焰粒子、碰撞火花、收集星尘爆点（Canvas 粒子池，~50 个上限）
- **挤压拉伸**：飞飞加速时沿速度方向拉伸、碰撞时压扁（纯视觉，不影响碰撞体）
- **音效节奏**：碰撞音效按速度分级（轻碰/重撞不同音调）

## 3. 摄像机与大世界系统（需求 2）

### 3.1 世界与视口分离（P0）

- `worldWidth/worldHeight` 语义改变：**真正的世界尺寸**（建议 300×200 起步，约为现在的 3 倍），关卡设计师不再受屏幕约束
- 引入**视口（viewport）**：相机位置 `(camX, camY)` + 缩放 `zoom`（固定 1.0，先不做缩放）
- `SceneRenderer` 渲染流程改造：
  ```
  ctx.save()
  ctx.translate(-camX * scale, -camY * scale)   // 世界→屏幕
  ctx.scale(scale, scale)
  draw(world)                                    // 只画视口内的实体
  ctx.restore()
  ```
- **视口裁剪**：只渲染与视口相交的实体（障碍物/收集品/触发器），大世界性能关键
- 现有 `setWorldSize/getVisibleWorldSize` 机制改造为相机变换（`contentOffsetX/Y` 居中逻辑可删除）

### 3.2 相机跟随策略（P0）

```
// 每帧（渲染前）：
targetX = feifei.pos.x + lookaheadX          // 前瞻：看向速度方向
camX += (targetX - camX) * followLerp        // 指数平滑，如 0.08
camX = clamp(camX, 0, worldW - viewW)        // 边界钳制，不露出世界外
```
- **前瞻量**：`lookahead = clamp(speed * 0.5, 0, 30)`，速度越快看得越远（Alto's 式）
- **死区模式**（可配置）：飞飞在屏幕中心死区（如 40% 区域）内移动时相机不动，出死区才跟——减少晃动
- **关卡可配置相机参数**：`camera: { lerp, deadzone, lookahead }` 加入 `LevelDef`，Boss 关可关闭前瞻（迷宫需要全局视野）

### 3.3 视差背景（P1）

- 星空改为 **3 层视差**：远景星云（0.1 系数）、中景星星（0.3）、近景星尘（0.6），按相机位置偏移
- 每章主题背景元素：惯性星→空间站轮廓、重力星→小行星地表、引力星→远处星球……（SVG/Canvas 绘制，沿用无图片资源原则）
- 背景生成改为**可平铺程序化生成**（seed 随机），支持大世界滚动

### 3.4 目标指示（P1）

- **屏幕边缘箭头**：终点/未收集星尘在视口外时，屏幕边缘显示方向箭头（半透明）
- 可选：终点光柱（贯穿全图的垂直光柱，远处可见）——比小地图更直觉，更适合低龄用户

## 4. 关卡数据重构与丰富（需求 3）

### 4.1 types.ts 扩展（P0）

```ts
// LevelDef 新增
export interface LevelDef {
  // ...现有字段
  viewport: { width: number; height: number }   // 视口尺寸（世界单位）
  camera?: { lerp?: number; deadzone?: number; lookahead?: boolean }
  goalType: 'reach' | 'collect' | 'dock' | 'survive'  // 目标类型
  hintText?: string        // 失败后提示（"试试提前减速？"）
  respawn?: boolean        // 是否有 checkpoint 复活
  entities: {
    platforms: PlatformDef[]     // 单向/移动平台
    springs: SpringDef[]         // 弹力垫
    portals: PortalDef[]         // 传送门（成对）
    conveyors: ConveyorDef[]     // 传送带
    gravityWells: GravityWellDef[]  // 引力井（从 trigger 升级为独立实体）
    hazards: HazardDef[]         // 危险区
  }
}

// 新实体示例
export interface PlatformDef {
  id: string
  x: number; y: number; width: number; height: number
  moveAxis?: 'x' | 'y'       // 移动平台
  moveRange?: number
  moveSpeed?: number
}
export interface SpringDef {
  id: string
  x: number; y: number; width: number; height: number

  direction?: Vec2           // 默认向上
}
export interface PortalDef {
  id: string; pairId: string // 成对传送
  x: number; y: number; radius: number
}
```

## 5. 操作方式与可玩性（需求 4）

### 5.1 操控优化（P1）

| 项 | 方案 | 参考 |
|----|------|------|
| 摇杆死区 | 加入 0.15 死区 + 指数响应曲线（小幅输入更精细） | 主机手柄标准 |
| **冲刺/脉冲** | 新增"脉冲引擎"：摇杆双击方向（触屏）或 Shift/空格（键盘）→ 1.5×推力持续 0.3s，冷却 1.5s，带音效+尾焰爆发 | Celeste dash / 赛车 boost |
| 触屏补充 | 摇杆保持为主（已验证），不加浮动摇杆（防误触） | — |
| 快速重试 | 失败界面自动聚焦"再试一次"，按 R/空格直接重开；死亡到重开 < 1s | Super Meat Boy |
| 暂停 | ESC/P + 按钮（已有），补"重新开始本关"按钮 | — |

### 5.2 可玩性增强（P1）

1. **失败模式丰富**：`hazard` 接触即失败、掉落出界失败、碰撞次数超限失败（对应各章主题）
2. **Checkpoint 复活**：已有 checkpoint 收集品类型（数据里用了 18 次），补齐"碰触即记录复活点、失败从复活点重开"逻辑
3. **渐进教学**：第一章 1-1→1-4 只加一个新概念（推力→惯性→速度控制→路线规划），用场景暗示，不用文字弹窗（呼应"先玩后悟"）
4. **反馈闭环**：所有动作（收集/碰撞/冲刺/通关）都有"音效+粒子+震动"三重反馈
5. **HUD 增强**：能量条（第 6 章）、冲刺冷却指示、目标方向箭头

### 5.3 手感参数建议（实施时校准）

| 参数 | 现值 | 建议 | 说明 |
|------|------|------|------|
| thrust | 0.06~0.08/帧 | 按 60fps 换算后微调 ±20% | 配合软限速 |
| 软限速 maxSpeed | 无 | 2.2~3.5（按关） | 全游戏统一手感 |
| 冲刺倍率 | 无 | 1.5×，0.3s，冷却 1.5s | 节奏操作 |
| 相机 lerp | 无 | 0.08~0.12 | 快速跟随不晕 |
| 相机前瞻 | 无 | 速度×0.5，上限 30 单位 | Alto's 式 |

| 风险 | 对策 |
|------|------|
| 物理参数改每秒量后手感漂移 | 换算后先跑全 30 关回归，参数只做 ±20% 微调 |
| 大世界 + 粒子性能 | 视口裁剪只渲染可见实体；粒子池上限 50；Canvas 单层 |
| 相机移动导致晕眩 | 死区模式 + 低 lerp 起步，Boss 关可关闭前瞻 |
| 关卡重设计破坏已通关进度 | 关卡 id 不变，进度只记 stars/时间，新布局不影响旧记录 |
| 冲刺破坏"惯性"教学 | 冲刺是有限资源（冷却），且第 1 章不出现在教学前 |
