## 0. 现状诊断（代码审计结论）

### 0.1 架构现状

| 模块 | 现状 | 问题 |
|------|------|------|
| 渲染 | `SceneRenderer`：整关世界缩放铺满 Canvas，`setWorldSize()` 计算统一 scale | **世界 = 屏幕**，无摄像机概念，关卡只能是一屏大小 |
| 物理 | `PhysicsEngine`：帧驱动，`engine.update(rt, 1)` **dt 硬编码为 1** | 物理速度随帧率变化（120Hz 屏会快一倍）；`timeAccumulator`/`lastTime` 声明了但从未使用 |
| 碰撞 | 圆-矩形碰撞 + 反弹解析（含防抖 hack） | 高速时可能穿透（无子步进）；无单向平台、无传送、无弹力垫等高级碰撞类型 |
| 触发器 | 引擎只实现 `boost` / `slow` / `wind` | **`gravity_well` 在数据中用了 11 次但引擎未实现**（第五章引力星关卡实际失效） |
| 关卡 | 30 关全部实现（6章×4普通+Boss），JSON 配置化 | 机制同质化：绝大多数是"障碍物+收集品+终点"三件套，关间差异主要靠物理参数数值 |
| 目标类型 | 只有"到达终点"（`goal.maxSpeed` 支持限速着陆） | 无收集赛/生存/竞速等多样目标 |
| 输入 | 4 方向键 + 摇杆（`thrustDir` 归一化向量） | 只有推力方向，无冲刺/蓄力等节奏操作，操控深度不足 |
| 失败模式 | 仅 `timeLimit` 超时失败 | 无掉落出界、碰撞上限等失败机制，压力感弱 |
| 进度 | `localStorage` + `SCHEMA_VERSION` 版本控制 | ✅ 结构良好，可平滑迁移 |

### 0.2 核心结论

游戏骨架完整、代码整洁，但**可玩性天花板被三个结构性限制卡住**：
1. **单屏世界**：关卡无法做大，缺乏探索感和纵深
2. **帧率相关物理**：手感在不同设备不一致，后续手感调优无从谈起
3. **机制单一**：物理实体类型少（只有障碍物/收集品/触发器三件套），关卡设计巧思施展不开

### 1.1 参考游戏与借鉴点

| **Jetpack Joyride / Asteroids** | 推力型操控的经典手感：软限速（推力效率随速度下降）、惯性滑行 | §2.4 手感 |
| **Alto's Adventure / Sky** | 跟随相机 + 运动方向前瞻 + 视差多层背景 | §3 摄像机 |

| **Angry Birds / Rayman** | 每关三星目标、收集品布局引导路线 | §4 关卡数据 |
| **Limbo / Inside** | 镜头缓慢推拉、氛围背景层 | §3.3 视差 |

### 1.2 提炼出的设计原则

1. **手感优先**：物理引擎的终极目标是"可控的惯性"——既要有惯性（教学点），又不能失控（挫败感）
2. **相机即叙事**：镜头引导视线，先看到目标再规划路线
3. **一关一机制**：每关只教一个核心概念，机制间不混战（呼应"先玩后悟"理念）
4. **失败要快**：快速重试降低挫败感，鼓励尝试（SM 肉男孩原则）

## 2. 物理世界引擎优化

### 2.1 帧率无关的固定时间步长（P0）✅ 已实施

**目标**：物理在任何帧率下表现一致（60/90/120Hz、低端机 30fps）。

**实施方式**（`useGameLoop.ts` + `PhysicsEngine.update()`）：
```
// 物理保持 60Hz 固定节拍，渲染跟随 rAF（显示帧率无关）
realDt = (rAF时间差) / 16.667            // 归一化到 60fps 帧单位，上限 5 帧
accumulator += realDt
while (accumulator >= 1 && steps < 5) {  // 最多补 5 步，防死亡螺旋
  engine.update(rt, 1)                   // 固定 dt=1
  accumulator -= 1
}
// 引擎内部再子步进：update 把 dt=1 拆成 2×0.5，防高速穿透
```
- 保留了原有"每帧单位"参数体系（`thrust 0.07` 等），**30 关数据零迁移**，手感与调优成果不破坏
- `slow` 触发器按步长缩放（`1 - 0.05*dt`），子步进下总效果不变
- 与方案初稿（换算为每秒量 + 120Hz）的差异：**用"固定 60Hz + 子步进"达到同样的帧率无关目标，但免去全部参数换算**，回归风险更低

### 2.2 碰撞系统增强（P0）✅ 已实施

1. **子步进防穿透** ✅：高速移动时每帧物理步内再分 2 子步检测，杜绝高速穿墙
2. **新增碰撞类型** ✅（types.ts 扩展 + 引擎实现）：

| 类型 | 行为 | 用途 |
|------|------|------|
| `platform`（单向平台） | 仅从上方碰撞（`resolvePlatformCollision`），从下方/侧面穿过 | 跳跃峡谷、过山车 |
| `spring`（弹力垫） | 接触即施加方向冲量（`dirX/dirY*power`），12 帧冷却防连弹 | 弹力星跳板 |
| `portal`（传送门） | 接触即传送到配对门（保持速度），20 帧冷却防来回传送 | 迷宫捷径 |
| `conveyor`（传送带） | 区域内持续表面推力（`forceX/forceY`） | 阻力星、能量星 |
| `hazard`（危险区） | 接触即失败（`state='lost'`） | 陨石带、暴风雪 |

3. **碰撞响应分级**：静态障碍（反弹）→ 单向平台（站立）→ 弹力垫（施力）→ 危险（失败）✅
4. 全部可选字段（`LevelDef.springs/portals/conveyors/hazards`），旧关卡零改动；已通过引擎模拟逐一验证 ✅

### 2.3 力系统完善（P0/P1）

1. **实现 `gravity_well`（引力井）** ✅ 已实施：修复现有失效关卡
   ```
   对每个引力井：以区域中心为圆心，半径 R = max(w,h)/2 的圆形力场
   方向：指向井心（force>0 拉扯）/ 远离井心（force<0 推离）
   大小：恒定 |force|（与现有 boost/wind 语义一致），核心 0.5 单位死区防抖动
   ```
   设计文档 §5 引力星的关卡（轨道、弹弓、三体）全部依赖此机制
2. **风区增强**：支持场内渐变力（按 x 位置线性插值力度），暴风雪 Boss 用
3. **软限速**：速度越接近 `maxSpeed`，推力效率越低（`thrust_eff = thrust * (1 - v/v_max)²`），自然形成终端速度——阻力星主题直接受益，且全游戏手感更稳

### 2.4 手感优化（Game Feel）（P1）✅ 已实施

- **软限速** ✅：`maxSpeed` 可选参数，速度越接近上限推力效率越低（验证：平滑收敛到上限）
- **屏幕震动** ✅：碰撞 3.5px / 边界反弹 1.2px，指数衰减
- **粒子效果** ✅：收集金星爆点、弹力垫橙粒（Canvas 粒子池，120 上限）
- **冲刺爆发** ✅：1.6× 推力 + 尾焰加长加亮（视觉反馈）
- **推力平滑/挤压拉伸**：待 P1-3 按需补充

## 3. 摄像机与大世界系统（需求 2）

### 3.1 世界与视口分离（P0）✅ 已实施

- `worldWidth/worldHeight` 语义改变：**真正的世界尺寸**（可大于视口，相机负责平移）
- 视口（viewport）：高度固定 75 世界单位（一屏基准），宽度按画布纵横比推导；世界比视口大 → 相机滚动，世界比视口小 → 居中（**旧关卡零回归**）
- `SceneRenderer` 相机变换：`translate(-camX*scale, -camY*scale) + scale`，`setCamera()` 自动钳制在世界范围内
- **视口裁剪**：只渲染与视口相交的实体（障碍物/收集品/触发器），大世界性能关键
- 缩放语义变化：从"世界完整可见"改为"视口铺满画布"（旧关卡在 16:9 画布下视觉完全一致；超扁画布下有 ≤16% 放大，可接受）
- 已验证：世界 300 宽测试关，飞飞高速飞行时相机保持其在视野内（像素追踪验证）

### 3.2 相机跟随策略（P0）✅ 已实施

```
// 每帧（渲染前）：
targetX = feifei.pos.x + lookaheadX          // 前瞻：看向速度方向
camX += (targetX - camX) * followLerp        // 指数平滑，默认 0.08
camX = clamp(camX, 0, worldW - viewW)        // 边界钳制，不露出世界外
```
- **前瞻量**：`lookahead = clamp(speed * 3, 0, 15)`，速度越快看得越远（Alto's 式）✅
- **关卡可配置**：`LevelDef.camera = { lerp, lookahead }`（types.ts 已加 `CameraConfig`）✅
- 死区模式（deadzone）：留待 P1-2 手感阶段按需补充

### 3.3 视差背景（P1）✅ 基础版已实施（多层星空）

- 星空 3 层视差：每颗星带 `parallax` 系数（0.1 远景 ~ 0.5 近景），按相机位置偏移 + 屏幕回绕 ✅
- 章节主题背景元素（空间站轮廓、星球、星云等）：待 P2 按章补充

### 3.4 目标指示（P1）

- **屏幕边缘箭头**：终点/未收集星尘在视口外时，屏幕边缘显示方向箭头（半透明）
- 可选：终点光柱（贯穿全图的垂直光柱，远处可见）——比小地图更直觉，更适合低龄用户

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 物理参数改每秒量后手感漂移 | 换算后先跑全 30 关回归，参数只做 ±20% 微调 |
| 大世界 + 粒子性能 | 视口裁剪只渲染可见实体；粒子池上限 50；Canvas 单层 |
| 相机移动导致晕眩 | 死区模式 + 低 lerp 起步，Boss 关可关闭前瞻 |
| 关卡重设计破坏已通关进度 | 关卡 id 不变，进度只记 stars/时间，新布局不影响旧记录 |
